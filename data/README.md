
# Datasets

This document lists the datasets used in the **XGB_Benchmark** project.

The goal of this benchmark is to evaluate whether XGBoost intrinsic feature-importance metrics (Gain, Cover, and Weight) can provide feature subsets with predictive performance comparable to those selected using SHAP across a wide range of tabular datasets.

---

# Dataset Selection Criteria

Datasets included in this benchmark should satisfy the following criteria:

- Tabular data
- Supervised classification task
- Publicly available
- Sufficient number of samples
- Sufficient number of features
- Well-documented source
- Widely used in machine learning research

The benchmark aims to include datasets from multiple application domains, including healthcare, cybersecurity, finance, manufacturing, biology, and general machine learning.

# Evaluation Strategy

For every dataset, the following pipeline will be applied:

1. Load dataset
2. Data preprocessing
3. Train XGBoost
4. Extract Gain, Cover, and Weight feature importance
5. Compute SHAP values
6. Select the top-k features
7. Train an interpretable downstream model
8. Evaluate predictive performance
9. Compare computational cost
10. Save all results

---

# Downstream Models

The benchmark will initially evaluate:

- Decision Tree
- Logistic Regression
- Linear SVM

Additional interpretable models may be incorporated in future versions.

# Data Directory

This directory contains all datasets and supporting artifacts used throughout the **XGB_Benchmark** project. It provides a standardized organization for storing raw datasets, canonical processed datasets, inspection reports, and documentation describing the data management workflow.

The objective of this organization is to ensure that every benchmark experiment is conducted using datasets that are reproducible, traceable, and prepared according to a consistent set of deterministic rules.

---

# Directory Structure

```text
data/
│
├── README.md
├── INSPECTION.md
├── PROCESSING.md
│
├── raw/
│   └── <dataset_key>/
│       ├── data.csv
│       ├── metadata.json
│       └── README.md (optional)
│
├── processed/
│   └── <dataset_key>/
│       ├── data.csv
│       └── metadata.json
│
└── reports/
    ├── inspection_report.json
    └── inspection_summary.csv
```

Each component serves a distinct purpose within the benchmark pipeline.

---

# Raw Datasets

The `raw/` directory contains the original datasets obtained from their respective sources.

Every dataset is stored in its own directory using the following layout:

```text
raw/
└── <dataset_key>/
    ├── data.csv
    └── metadata.json
```

Some manually downloaded datasets may additionally include a `README.md` containing source-specific notes or download instructions.

Raw datasets are preserved in their original published form whenever possible. They are never modified directly by the benchmark pipeline.

---

# Processed Datasets

The `processed/` directory contains the canonical datasets generated by `prepare.py`.

Each processed dataset consists of:

- `data.csv` — the canonical processed dataset used by all benchmark experiments;
- `metadata.json` — detailed metadata describing the preparation process, feature transformations, target encoding, and dataset characteristics.

Processed datasets are deterministic. Running the preparation pipeline multiple times on the same raw dataset always produces identical outputs.

---

# Inspection Reports

The `reports/` directory contains reports generated by `inspect_raw.py`.

These reports summarize the structural and statistical characteristics of every raw dataset and provide the information required to design and validate the preparation pipeline.

The reports are generated automatically and are intended for diagnostic purposes.

---

# Dataset Workflow

Every dataset follows the same lifecycle throughout the benchmark:

```text
Raw Dataset
      │
      ▼
inspect_raw.py
      │
      ▼
Inspection Reports
      │
      ▼
prepare.py
      │
      ▼
Canonical Processed Dataset
      │
      ▼
Benchmark Experiments
```

This separation ensures that dataset inspection, canonical preparation, and experimental preprocessing remain independent responsibilities.

---

# Documentation

Additional documentation describing each stage of the data pipeline is provided in the accompanying documents:

- **INSPECTION.md** — describes the design and responsibilities of `inspect_raw.py`, including the information collected during dataset inspection and the generated reports.

- **PROCESSING.md** — defines the canonical dataset preparation policy implemented by `prepare.py`, including the deterministic transformations applied to every dataset before benchmarking.

Together, these documents specify the complete data management workflow adopted throughout the **XGB_Benchmark** project.

---

# Reproducibility

The benchmark is designed so that every processed dataset can be traced back to:

- its original raw dataset;
- the corresponding inspection results;
- the preparation metadata;
- and the documented preparation policy.

This design ensures that benchmark experiments remain fully reproducible while allowing additional datasets to be incorporated into the framework without changing the underlying preparation philosophy.
